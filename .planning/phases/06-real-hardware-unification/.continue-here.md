## Critical Anti-Patterns (do NOT repeat these)

- **Don't start tooling work when the priority is real-hardware testing.** This session was supposed to be priority 1 calibration; instead it became a SwiftUI app + parity report. Both useful, neither advanced Phase 6. **Mitigation:** at session start, read the HANDOFF priority list and explicitly commit to ONE priority before any code is written. Tooling is only justified when it directly unblocks the named priority.
- **Don't add code to "fix" a problem before verifying the diagnosis with a web/upstream check.** I spent significant time on `find_camera.py` "auto-shift" hardening before web-searching OpenCV issues + reading `cv2-enumerate-cameras` source confirmed the diagnosis was wrong. **Mitigation:** when a third-party library is involved, web-search known-issue hits BEFORE writing defensive code; if upstream has a different mental model than mine, mine is the one to update.
- **Don't pass empty/whitespace strings through @AppStorage to spawned scripts.** EpisodeBrowser had a `repoId = "\n"` corruption (user accidentally hit Enter on empty field, newline persisted across launches) that triggered HF Hub validation crashes deep in `huggingface_hub.utils._validators`. **Mitigation already in place:** TextField `.onChange` strips newlines on input + `sanitizeRepoId()` helper before each spawn + Python scripts default-synthesize a `local/<dirname>` placeholder when `--repo-id` is empty and `--root` is given.
