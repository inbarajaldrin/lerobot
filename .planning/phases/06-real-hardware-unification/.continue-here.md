<decisions_made>

Major design decisions captured this phase (full rationale in HANDOFF.json):
- sim_ground_truth uses **gz.transport13 directly**, not ros_gz_bridge. The bridge's Pose_V → TFMessage conversion silently drops `pose.name` and `pose.id` — verified live, both `frame_id` and `child_frame_id` come through empty.
- Cup `drop_<color>` frames are **sibling top-level SDF models**, not child links. Top-level models get absolute world poses in Gazebo's Pose_V; child links get parent-relative. Mirrors Isaac's wrapper-Xform-prim pattern.
- aruco_camera_localizer is **auto-cloned by bootstrap.sh to /tmp** rather than added as a git submodule. `git submodule add` hits a pack-index bug on macOS spaced paths (verified — fails with `tmp_pack_*` write error). Cloning to /tmp + symlinking is the working substitute.
- so_arm101_bringup **copies** `camera_publisher` from aruco_camera_localizer rather than depending on it. Keeps the lerobot real-hw stack self-contained; one source of camera frames, multiple consumers (recorder, aruco localizer, etc.).
- `record_sim.sh → record.sh` rename with **back-compat symlink**. The wrapper is mode-agnostic now (sim+real), but no existing reference breaks.

</decisions_made>

<context>
This was a long, focused single-session sprint that took Phase 6 from "planned" to "code+docs complete pending hardware". The mental model was: every architectural decision needed to mirror what isaac-sim-mcp@so-arm101 does on the Isaac side so that `control_gui` (the consumer) sees identical topic shapes regardless of producer. That parity north star drove the gz.transport13 choice, the sibling drop-frames pattern, the matching topic names (`/drop_poses`, `/objects_poses_sim`, `/objects_bbox_sim`), and the matching `child_frame_id` conventions (`drop_red`/`green`/`blue`, object-name strings).

The doc work at the end (CLAUDE.md cascade + ROS2_PLUGINS.md) was a deliberate counter to a real gap: prior to this, an agent picking up the project from a fresh clone would have inherited the unrelated `~/Documents/.../agents/ros2/CLAUDE.md` (o2ac-ur flavored) as its closest-scope context, and the `so101_ros2` plugin pattern wasn't documented anywhere — would-be plugin authors had to reverse-engineer it from the source. Both are now closed.

If 6-07 fails when hardware arrives, suspect (in order): (a) jointstatereader serial config — `inter_servo_delay_s` defaults are tuned for one specific Feetech firmware revision; (b) camera resolution downgrade — AVFoundation often refuses arbitrary `set()` calls and the camera_publisher's WARN-on-downgrade log will tell the truth; (c) `--robot.cameras` default mismatch — the wrapper assumes 2 cameras, single-cam rigs need a CLI override (documented in HANDOFF human_actions_pending).
</context>
