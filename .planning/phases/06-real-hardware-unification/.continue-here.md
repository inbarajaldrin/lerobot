# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure
> in this session. Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: **Do NOT enable `r_hat_enabled=true` on `trajectory_shim`** — the online learner has a broken signal path (i_term decoupled from plant after replacing with r_hat → invalid label). Re-enabling makes K_res oscillate wildly per goal and injects noise into the live trajectory as visible shake. The code is intentionally retained as scaffolding; only re-enable WITH a static `K_res` produced by an offline calibration script (next session task #4). Structural mitigation: parameter defaults to `False`; the comment block in `__init__` documents the bugs explicitly.

- [ ] CONSTRAINT: **Do NOT theory-fix motion-quality issues without baseline measurement.** Half this session's iterations chased the wrong root cause because we trusted intuition over data. The empirical loop (record → inspect → propose → measure-diff) is now codified in `mac-env/scripts/diagnose_ticks.sh`. Use it. Structural mitigation: `MEMORY.md` "Motion-quality stack" section + diagnostic toolchain promoted to permanent paths.

- [ ] CONSTRAINT: **Do NOT chase sub-1° static accuracy by tweaking integrator/FF/K_calib alone.** STS3215 firmware deadband (~0.88°) + mechanical backlash (~0.87°) = ~1° hardware noise floor. Sub-deg precision requires either (a) lowering the servo's `0x1A`/`0x1B` insensitive-zone EEPROM registers (trade-off: buzz/wear), or (b) offline K_res calibration combined with the existing r_hat scaffolding. Adding more poses to K_calib alone will not move the needle below ~1°. Structural mitigation: Robo9 measurements cited in `MEMORY.md`.

**Do not proceed until all boxes are checked.**
