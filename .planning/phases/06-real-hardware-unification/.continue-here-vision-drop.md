## Critical Anti-Patterns (do NOT repeat these)

| Pattern | Description | Severity | Prevention |
|---------|-------------|----------|------------|
| In-place EEPROM Homing rewrite while torque on | The `recenter_one_to_commanded` service built earlier this session caused 250° physical motion on cable-loaded joints. GPT confirmed via Feetech protocol manual: Goal_Position is interpreted in post-Homing coords, so changing Homing implies a hold-target shift the firmware doesn't rebase. Torque-off cycle trades PD jolt for cable/gravity sag. | blocking | Use `lerobot-calibrate` (via `calibrate_arm.sh`) for bulk drift, `freedrive_one + recenter_one` for single-joint hand-positioned drift. Never invent a third path. |
| Trusting audit script output without sanity check | `feetech_calib_audit.py` was reading EEPROM Homing_Offset as int16 but Feetech firmware stores it as 12-bit sign-magnitude. False MISMATCH on 4 of 6 joints sent us down a 3-hour rabbit hole. | advisory | When an audit shows surprising results, cross-check by `cat`-ing the JSON file directly and decoding the EEPROM value manually. Now fixed in the script as of 6730571. |
| Theory-based fixes without measurement | Earlier in this session I "fixed" smoothness via cubic Hermite + 50 Hz (correct fix) but missed that the user-visible jerk was actually gravity-comp under-compensation. Only after `record_motion_topics.py + analyze_motion.py` revealed the integrator was stalled did the right fix surface. | advisory | Run `mac-env/scripts/record_motion_topics.py` BEFORE making motion-path changes (baseline) and AFTER (validation). Compare hold_e/settle/f_osc columns. |

## ▶ NEXT-PHASE WORK PLAN — vision + drop

### Step 1 — Vision pipeline calibration (yoloe X/Y/Z accuracy)

**Goal**: characterize the systematic bias in yoloe-derived object poses against
tape-measured ground truth, then either (a) update aruco_camera_localizer's
calibration offset OR (b) tune the Real Grasp Z-floor spinbox to compensate.

**Procedure**:

1. **Place a known reference**: a printed checkerboard, OR a single lego at
   a tape-measured table position (X/Y/Z relative to base frame).
2. **Stack up in real mode**, wrist cam looking at the reference.
3. **Capture yoloe output** for ~20 seconds while the wrist is stationary:
   ```bash
   pixi run --manifest-path /tmp/mac-env/pixi.toml bash -c \
     'source /tmp/soarm-ws/install/setup.bash && \
      export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp && \
      export CYCLONEDDS_URI="file:///tmp/mac-env/cyclonedds.xml" && \
      ros2 topic echo /objects_poses_real --max-count 200' | \
     tee /tmp/yoloe_static.yaml
   ```
4. **Compute mean + stdev per axis** vs the tape-measured truth. Look for:
   - Constant bias (mean ≠ truth) → adjust `aruco_camera_localizer/config/robot_config.yaml` `calibration_offset_*` fields
   - High stdev → wrist camera shake; check mounting
5. **Repeat with the wrist at multiple poses** (move base by hand, recheck) —
   yoloe error often varies with viewing angle.

### Step 2 — Place cup ArUco markers (human action)

Mount **DICT_4X4_250** markers (25 mm size per SDF spec) on top of each
colored cup. Marker IDs must match what's in
`aruco_camera_localizer/config/robot_config.yaml` (search "drop_red" /
"drop_green" / "drop_blue"). Once placed, verify:

```bash
ros2 topic hz /drop_poses
# Expected: ~1 Hz publish rate when at least one cup marker is in wrist FOV
```

### Step 3 — Drop pipeline end-to-end

With cup markers placed and `/drop_poses` populating:

1. Click **Refresh Drops** in Grasp tab → drop targets listbox populates with `drop_red`, `drop_green`, `drop_blue`
2. Move arm to grasp_home, click **Grasp Move** on a real lego → arm picks
3. Click **Drop Point** with a cup target selected → arm pans to face the cup
4. Click **Drop Sweep** → arm sweeps wrist down to release block
5. Verify lego physically lands in the cup

If drop motion fails: check `/check_state_validity` (cup collision padding may need adjustment in real mode), and `/tmp/last_arm_trajectory.json` for the executed waypoints.

### Step 4 — Pick-and-drop full cycle

Test full cycle multiple times (3-5 reps) to validate reliability:
- Grasp Home → detect lego → Grasp Move → Grasp Close → Drop Point → Drop Sweep → Grasp Home

Watch for:
- Lego not gripped firmly (adjust Real Grip Close spinbox in Grasp tab)
- Arm trajectory hits cup wall (adjust _CUP_COLLISION_PADDING in control_gui.py)
- Drop misses cup (adjust drop_hover_above_rim spinbox)
